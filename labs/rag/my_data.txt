개념 먼저 박살내는 타입
너는 단순히 "코드가 돌아가게"보다 "이게 정확히 뭐냐"를 먼저 집요하게 물어본다.
예: collection 뭐냐, embedding function 뭐냐, 재귀냐 아니냐
특징: 블랙박스 못 참음, 내부 구조 이해해야 납득됨

흐름 중심 사고 (Flow-oriented)
너 질문 대부분이 이거임: "그래서 전체 흐름이 어떻게 돌아가는데?"
단편 지식보다 시작 → 처리 → 결과, 시스템 흐름을 중요하게 봄

애매한 설명 싫어함
선호: "이건 ~다" (단정형), 맞다 / 아니다
비선호: 두루뭉술, 가능성 나열

실무 감각 빠르게 잡는 스타일
embedding → vector DB → collection → RAG
이건 그냥 공부가 아니라 "이거 실무에서 어떻게 쓰이냐"로 가는 루트

의심 기반 이해 (좋은 쪽)
예: "이거 재귀 아니냐?", "이거 도커 없이 왜 돌아가냐?", "이거 위치 어디냐?"
특징: 그냥 받아들이지 않음, 항상 구조 의심함. 이건 엔지니어로는 장점임

속도 빠른 대신, 중간 생략 있음
이미 꽤 앞까지 이해했는데 기초 개념을 뒤늦게 다시 묻는 경우 있음.
예: RAG까지 왔는데 collection 다시 확인
특징: 빠르게 올라감, 대신 중간에 빈칸 생김 → 다시 메움

종합 스타일 한 줄 정리
흐름 기반으로 시스템을 이해하려고 하고, 내부 구조를 납득할 때까지 파고드는 타입

장점
아키텍처 이해 빠름, 실무 전환 속도 빠름, 블랙박스 의존 안 함

주의할 점
모든 걸 100% 이해하려 하면 속도 느려질 수 있음. 어떤 건 "그냥 쓰는 레벨"도 필요함

추천 방향
너 스타일에 맞는 학습 방식: 전체 흐름 → 핵심 20%만 깊게 → 나머지는 사용하면서 채우기
